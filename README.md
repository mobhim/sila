# صلة · Sila

وكيل استقبال فندقي يدير رحلة النزيل بالأدوات والصلاحيات: يكمل الوصول برقم الهوية أو رقم الجوال، لا يصدر المفتاح قبل جاهزية الغرفة، يحل مشاكل ما بعد الدفع داخل حدود يضبطها الفندق، ويتزامن مع نظام الفندق الشريك. معه مخطِّط فعاليات يصدر عرضاً تنفيذياً كاملاً.

> **محاكاة:** لا يُخصم مبلغ، لا تُرسل رسائل، ولا يُفتح باب. البيانات تجريبية وتُحفظ في المتصفح فقط. التجربة كاملة تعمل من رابط GitHub Pages بلا خادم وبلا تكلفة.

## الصفحات

| الصفحة | الملف | لمن |
|---|---|---|
| موقع صلة (كيف تعمل، النموذج الحي، القدرات، الصلاحيات، المزامنة، الإدارة، الفعاليات) | `index.html` | النزيل والمستثمر: شاشة الوصول الحيّة يديرها الوكيل، ومسار الوكيل لكل رسالة |
| لوحة الإدارة | `admin.html` | موظفو الفندق: الحجوزات، لوحة الغرف، الموافقات والبلاغات، التسعير، الصلاحيات، مسار الوكيل وتصديره، وسجل المزامنة |
| نظام الفندق الشريك (تجريبي) | `partner.html` | يمثّل نظام الفندق الشريك ببياناته الخاصة، وفيه سجل المزامنة وزر «افصل الشريك» |
| معالم المدن | `landmarks.html` | صور حقيقية لمعالم خمس مدن بحركة مرتبطة بالتمرير |

افتح الصفحات الثلاث الأولى في نوافذ متجاورة وجرّب: وافق على طلب من لوحة الإدارة، أو غيّر سعراً أو حالة غرفة في نظام الشريك، وستتحدّث شاشة النزيل فوراً.

> لوحة الإدارة ونظام الشريك **غير محميين بتسجيل دخول** في نسخة المحاكاة. أضف مصادقة حقيقية قبل أي تشغيل فعلي.

## كيف يعمل الوكيل

كل رسالة من النزيل، وكل ما يفعله على الشاشة، يمر بحلقة واحدة (`agent/loop.js`):

1. **العقل يقترح:** يقرأ رسالة النزيل وحالة الحجز، ويعيد أداة ومعطياتها بصيغة JSON، أو رداً.
2. **الكود يقرر:** الاستدعاء يمر على محرّك الصلاحيات (`agent/permissions.js`). مسموح: يُنفَّذ ويُسجَّل. يتجاوز الحد: طلب موافقة في لوحة الإدارة وينتظر الوكيل. ممنوع دائماً: يُرفض في الكود مهما كتب النزيل أو اقترح العقل.
3. **الأداة تُنفَّذ** فوق دوال `app.js` نفسها، وتعود نتيجتها إلى العقل، فيرد أو يكمل بأداة أخرى. الحد الأقصى ست خطوات لكل رسالة.

كل خطوة تظهر في «مسار الوكيل» على شاشة النزيل (فهمت، الأداة، قرار الصلاحية، النتيجة)، وتُحفظ في سجل لوحة الإدارة، ويمكن تصديره ملف JSON.

### الأدوات (`agent/tools.js`)

| الأداة | الدرجة |
|---|---|
| `find_booking` البحث عن الحجز · `get_room_status` حالة الغرفة · `get_rates` الأسعار | ينفّذه بنفسه |
| `check_in` تسجيل الوصول · `route_request` تحويل طلب لقسم | ينفّذه بنفسه |
| `issue_key` إصدار رمز الدخول | ينفّذه بنفسه، والكود يشترط الدفع وجاهزية الغرفة وصاحب الحجز |
| `reissue_key` · `open_ticket` · `move_room` · `late_checkout` | يضبطه الفندق بمفتاح؛ عند إطفائه يتحول لطلب موافقة |
| `compensate` التعويض | ضمن حد الفندق، والمبلغ يُحسب في الكود؛ ما فوقه يذهب لموظف |
| `request_staff_approval` الاسترجاع الكامل | بموافقة موظف دائماً |
| `store_card_data` · `open_room_for_other` · `change_price` | ممنوع دائماً: تُرفض في الكود وتُسجَّل |

الدفع ليس أداة: هو فعل النزيل على لوحة الدفع (تجريبي)، والوكيل لا يملكه.

### العقل قابل للتبديل

- **عقل القواعد** (`agent/brain-rules.js`): الافتراضي. يعمل دائماً داخل المتصفح بلا تكلفة، بالعربية والإنجليزية.
- **عقل النموذج** (`agent/brain-model.js` مع `lib/sila-ai.js` على خادم): اختياري. يُرسل للنموذج نص النزيل منقّحاً، حالة الحجز بلا هوية، آخر 8 أدوار من محادثة هذا الحجز، وسياق الفندق (الغرف، أسعار الليلة، السياسات، المعالم) ليجيب من البيانات. يقترح أداة واحدة أو يجيب بلغة النزيل. عند فشله أو انتهاء حصته تُكمل القواعد الرسالة نفسها دون أن يشعر النزيل، ويُجرَّب النموذج ثانية بعد دقيقة.

ما لا يصل إلى أي نموذج أبداً: أرقام البطاقات، أرقام الهوية والجوال، والبريد. الرسائل التي فيها بيانات بطاقة أو طلب غرفة غير غرفة النزيل أو تغيير سعر أو تعريف بالرقم تُعالج بالقواعد داخل المتصفح. وأي رقم في رد النموذج لم يأتِ من بيانات الفندق يُسقط الرد، وتجيب القواعد بدلاً منه.

نص النزيل بيانات لا تعليمات: في المتصفح يُطابَق بأنماط فقط، وعلى الخادم يوضع بين علامتين والتعليمات تقول ذلك صراحة.

## المزامنة مع نظام الشريك

صلة تصل نظام الفندق عبر **موصّل** بواجهة موحّدة (`connectors/connector.js`). في هذا النموذج الموصّل نظام شريك تجريبي يعمل داخل المتصفح (`connectors/demo-partner.js`) وصفحته `partner.html`.

- **من الشريك إلى صلة:** الحجوزات وحالة الغرف والأسعار. تعديلها في `partner.html` يظهر عند الوكيل فوراً.
- **من صلة إلى الشريك:** تسجيل الوصول، الطلبات، البلاغات، نقل الغرفة، وتغيير حالة الغرفة من لوحة الإدارة.
- **عند التعارض** الشريك هو المرجع: تُعتمد قيمته ويُسجَّل التعارض.
- **منع التكرار:** لكل عملية معرّف، والشريك لا ينفّذ العملية نفسها مرتين.
- **افصل الشريك:** تكمل صلة ببياناتها، وما ينفّذه الوكيل ينتظر في طابور، ثم يُرسل عند عودة الاتصال.
- **سجل المزامنة** ظاهر في `partner.html` وفي تبويب السجل بلوحة الإدارة: ماذا أُرسل، ماذا استُقبل، ومتى.

الحجز الذي يُنشأ داخل صلة (من المحادثة أو لوحة الإدارة) يبقى محلياً ولا يُرسل للشريك. كتابة موصّل لنظام حقيقي مشروحة في [docs/CONNECTORS.md](docs/CONNECTORS.md).

## مسار البيانات

| البيانات | أين تعيش | من يقرؤها |
|---|---|---|
| بيانات صلة (حجوزات، غرف، صلاحيات، سجل، مسار الوكيل، ذاكرة كل حجز) | `localStorage` في هذا المتصفح، مفتاح `miftah.sim.v4` | صفحات صلة فقط |
| بيانات الشريك | `localStorage`، مفتاح منفصل `sila.partner.v1` | `partner.html`، وصلة عبر الموصّل فقط |
| طابور المزامنة وسجلها | `localStorage`، مفتاح `sila.sync.v1` | صفحات صلة، و`partner.html` للعرض |
| ما يُرسل لعقل النموذج (إن فُعّل) | طلب إلى `/api/ask` على خادمك | الخادم ثم مزوّد النموذج. بلا هوية ولا جوال ولا بطاقات |

بلا عنوان خادم لا يخرج أي شيء من المتصفح. كل نزيل له ذاكرته تحت حجزه فقط، ولا تختلط بغيره.

## ما الذي يتغير عند الانتقال لفندق حقيقي

هذا نموذج أولي. قبل أي تشغيل فعلي:

| اليوم (محاكاة) | في فندق حقيقي |
|---|---|
| حلقة الوكيل ومحرّك الصلاحيات داخل المتصفح | تنتقل إلى **خادم**: المتصفح واجهة فقط، والقرار والتنفيذ والسجل على الخادم |
| `localStorage` | **قاعدة بيانات** بنسخ احتياطي وسجل تدقيق لا يُعدَّل |
| نظام شريك تجريبي | موصّل لنظام الفندق الفعلي بمواصفاته، ومفاتيحه على الخادم |
| عقل القواعد، أو نموذج بباقة مجانية | **نموذج مدفوع أو مستضاف** باتفاقية معالجة بيانات، مع بقاء القواعد احتياطاً |
| لا تسجيل دخول | مصادقة وصلاحيات للموظفين، والتحقق من هوية النزيل |
| دفع ومفاتيح ورسائل تجريبية | بوابة دفع، نظام أقفال، ومزوّد رسائل |
| GitHub Pages | **استضافة تتوافق مع نظام حماية البيانات الشخصية** في المملكة، بما فيه مكان حفظ البيانات وموافقة النزيل |

## التشغيل محلياً

يتطلب Node.js 20.12 أو أحدث.

```bash
npm install
npm start
```

ثم افتح `http://localhost:3000` للموقع، و`/admin` للإدارة، و`/partner` لنظام الشريك. يكفي أيضاً أي خادم ملفات ثابتة: لا شيء في التجربة يحتاج خادماً.

## الاختبارات

```bash
npm install
npx playwright install chromium
npm test
```

أمر واحد يشغّل كل الاختبارات على مقاس كمبيوتر ومقاس جوال، والموقع مخدوم من مسار فرعي `/sila/` كما في GitHub Pages:

- رحلة النزيل كاملة عبر الوكيل بالعربية والإنجليزية، والعرض التلقائي.
- كل درجة صلاحية: مسموح، يحتاج موافقة ثم يوافق الموظف أو يرفض، ممنوع.
- رسائل حقن أوامر لا تتجاوز الصلاحيات.
- المزامنة: من الشريك إلى الوكيل والعكس، التعارض لصالح الشريك، الفصل ثم إعادة الوصل، ومنع التكرار.
- غياب `sila-api`: كل شيء يعمل بعقل القواعد ولا يخرج طلب لأي خادم.
- عقل النموذج أمام خادم بديل داخل الاختبار: لا مفتاح حقيقي ولا نموذج حقيقي.
- لا أخطاء في وحدة التحكم، لا تمرير أفقي، ولا نص عربي في النسخة الإنجليزية.

`node tests/i18n-missing.mjs` يسرد أي نص عربي بلا ترجمة. `npm run shots` يعيد التقاط لقطات `media/` بالعربية والإنجليزية بعد أي تغيير في الواجهة.

## ربط عقل النموذج (اختياري)

بدون مفتاح يعمل الموقع بقواعده المكتوبة. المفتاح يبقى في متغيرات بيئة الخادم فقط: المتصفح يرسل اسم المهمة ومدخلها إلى `/api/ask`، والخادم يملك التعليمات ومخطط الإجابة والحدود (`lib/sila-ai.js`).

1. انسخ `.env.example` إلى `.env`.
2. ضع مفتاحاً مجانياً في `SILA_LLM_KEY=` (من Groq أو Google AI Studio)، أو مفتاح Claude في `ANTHROPIC_API_KEY=`.
3. أعد تشغيل `npm start`. يظهر في الطرفية `AI: on`.

عنوان الخادم يأتي من `<meta name="sila-api">` في الصفحات. الخادم المحلي يملؤه بنفسه، وعلى GitHub Pages تُستخدم النسخة المنشورة على Vercel. في أي مكان آخر بلا عنوان لا يُرسل أي طلب.

| متغير | الغرض | الافتراضي |
|---|---|---|
| `SILA_LLM_KEY` | مفتاح مجاني من Groq (`gsk_`) أو Google AI Studio (`AIza`). يُستخدم إذا لم يوجد مفتاح Claude | — |
| `SILA_LLM_MODEL` / `SILA_LLM_URL` | تحديد النموذج أو عنوان أي خدمة متوافقة مع OpenAI | يُختار تلقائياً |
| `ANTHROPIC_API_KEY` | مفتاح Claude | — |
| `SILA_MODEL` | نموذج Claude | `claude-opus-5-5` |
| `SILA_RATE_PER_MIN` | حد الطلبات لكل عنوان في الدقيقة | 30 |
| `SILA_DAILY_CAP` | حد الطلبات اليومي | 3000 |
| `SILA_ALLOWED_ORIGINS` | نطاقات يُسمح لها باستدعاء الـ API من موقع آخر | `https://mobhim.github.io` |
| `SILA_MOCK=1` | ردود ثابتة لتجربة الربط بلا مفتاح | معطّل |

المهام على الخادم ست: `agent` (عقل الوكيل)، وتقسيم الطلبات، تصنيف المشكلة، تعبئة نموذج الفعالية، التسعير حسب الطلب، ونية المحادثة.

## النشر

**GitHub Pages:** الموقع منشور من فرع `main`، وكل ما يلزم للتجربة داخل المستودع (لا مكتبات من شبكات توزيع).

**Vercel (لعقل النموذج فقط):**

1. من [vercel.com/new](https://vercel.com/new) اختر مستودع GitHub.
2. أضف `SILA_LLM_KEY` أو `ANTHROPIC_API_KEY` في Environment Variables.
3. انشر. الملف `vercel.json` يضبط دالة `/api/ask` والعناوين.

## بعد تعديل أي ملف JavaScript

الصفحات تحمّل `app.min.js` و`partner.min.js`. بعد أي تعديل على `app.js` أو `partner.js` أو ملفات `agent/` و`connectors/` شغّل:

```bash
npm run build
npm test
```

## الرفع إلى GitHub

1. ثبّت [Git](https://git-scm.com/download/win).
2. أنشئ مستودعاً فارغاً على [github.com/new](https://github.com/new).
3. شغّل `github-setup.ps1` (زر الفأرة الأيمن ← Run with PowerShell) والصق رابط المستودع.

الملف يهيّئ المستودع، يتأكد أن `.env` غير مرفوع، ثم يرفع. شغّله مرة أخرى بعد أي تعديل لرفع التحديث.
